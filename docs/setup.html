UR賃貸の空き部屋を自動で監視し、条件に合う新着が出たら Slack に通知するツールです。 この手順書はプログラミングの知識がない方を想定して書いています。 コードを書く必要はなく、画面の操作と設定値のコピー＆ペーストだけで完了します。

所要時間の目安：30〜60分。 アカウントを新しく作る場合は、その分が加算されます。
途中で分からなくなっても壊れることはないので、落ち着いて進めてください。

なぜこのツールを作ったのか

空室が出ても、向こうからは知らせてくれない

UR の公式サイトの「よくあるご質問」には、こういう問答があります。

Q. 希望する物件に空室が出たら連絡してくれるの？
A. 空室情報につきましては随時更新されておりますので、UR賃貸住宅Webサイトまたは店舗で ご確認ください。

つまり自分で何度も見に行くしかない、というのが公式の答えです。 気になる物件のページを、思い出すたびに開いて確かめることになります。

メールで届く公式サービスもあるが、対象が限られる

メールで知らせてくれる仕組みが、まったく無いわけではありません。UR には 空室情報お届けサービス があり、登録した条件に合う部屋の募集が始まるとメールが届きます。

ただし対象は子育て世帯と若者夫婦世帯に限られ、実施しているのも一部の団地だけです。 事前の申込みとマイページでの条件登録も必要になります。
ここから外れる人には使えません。まずご自分が対象になるか確かめて、 対象なら公式サービスのほうが確実です。このツールが要るのは、対象外だった場合です。

気づくのが遅れると取られる

そしてUR賃貸は、約70万戸のほとんどが抽選なしの先着順です （新築物件など一部は抽選になります）。 気づくのが数時間遅れただけで、もう他の人に決まっていた、ということが普通に起こります。

1件を見張るだけでも大変なのに、候補が複数あればなおさら現実的ではありません。 仕事中も、寝ている間も、人間が張り付き続けることはできません。

だから、入居したい物件を横断的に監視して、空きが出た瞬間に知らせる仕組みが要ります。 このツールはそのために作りました。

見張る作業は機械に任せて、人間は「見つけたらすぐ申し込む」という本当に大事な一手に集中できます。

通知が来たら、どうやって押さえるか

Slack 通知にはその部屋のページへのリンクが入っています。開くと、ページの中ほどに 「お部屋の内覧・お申込みのお問い合わせ」という欄があり、そこに2つの導線が並んでいます。

  • 電話で今すぐお問い合わせ — 担当の UR賃貸ショップの直通番号。 スマホならタップするだけで発信できます
  • ネットで仮申込み — その場で仮申込みまで進めます（ユーザー登録が必要）

一番速いのは、通知 → リンクをタップ → 電話ボタンをタップ、の流れです。 スマートウォッチで気づいて、スマホを取り出してこの3タップ。 早い者勝ちの世界では、この短さがそのまま効きます。

入居を決めてから動くのでは遅い

ここが一番大事なところです。UR の手続きは、こういう順番で組まれています。 

お申込み（仮申込）→ 内覧 → 書類提出（本申込）→ 契約 → 入居

注目すべきは「仮申込」が内覧より前にあることです。公式ページにも、この仮申込の 段階でお部屋の確保が行われると書かれています。 つまり、実際に部屋を見るのは、押さえたあとなのです。

だから「入居するかどうか」は、電話の時点では決まっていなくて構いません。 まず押さえて内覧の予約を取り、見てから考える。制度がそういう順番になっています。 迷っているあいだに他の人が押さえてしまえば、見ることすらできません。

押さえたあとには期限があります。公式ページに書かれているのは次のとおりです。

手続き期限
内覧お申込みの翌日から1週間以内
書類提出（本申込）仮申込の翌日から1週間以内
契約仮申込の翌日から10日以内

お申込みは一世帯につき一件です。 複数の部屋を同時に押さえておくことはできません。監視は何件でもできますが、 押さえるときは1室を選ぶことになります。

キャンセルの可否や条件については公式ページに明記がありません。 気になる場合は電話のときに直接確認してください。

補足：公式FAQには「電話によるお申込みは受け付けておりません」とあります。これは 申込み手続きそのものが電話で完結しないという意味で、電話してはいけないという話では ありません。物件ページが「内覧・お申込みのお問い合わせ」として電話番号を大きく出しているとおり、 まず電話で当たるのは正規のやり方です。ショップの営業時間外に通知が来たときは、 先にネットで仮申込みをしておく手もあります。

この手順書が扱うのは「空きに気づく」ところまでです。 そこから先の問い合わせ・内覧・契約は、UR の案内に従ってください。

このツールは何をするのか

UR賃貸のサイトを15分おきに自動で見に行き、あなたが指定した条件 （建物名・間取り）に合う部屋が新しく出たら、Slack に通知します。

全体の流れ

「15分おき」は約束ではありません

設定上は15分間隔ですが、GitHub が必ずその間隔で動かしてくれるわけではありません。 混雑しているときは遅れますし、その回の実行が飛ばされることもあります。

これは設定ミスでも故障でもなく、GitHub の自動実行がそういう性質のものだからです。 無料で借りている仕組みなので、時刻をきっちり守る保証がありません。

実際に30分間隔で運用していたときの記録がこちらです。設定は30分なのに、 間隔は46〜64分に広がり、9時間で18回動くはずが12回しか動きませんでした （およそ3分の1が飛ばされていた計算です）。 

02:17 → 03:21 → 04:07 → 05:00 → 05:54 → 06:47 → 07:35 → 08:34 → 09:30 → 10:27
  64分   46分   53分   54分   53分   48分   59分   56分   57分

15分に設定しているのは、試行の回数を増やして、実際の間隔を少しでも縮めるためです。 15分おきに動くようになるからではありません。期待できるのは 「実際には30分前後で動く」くらいのところだと思ってください。

何分おきに動いたかは、あとから正確に分かります。 実行のたびに記録がリポジトリに残るので、リポジトリの Commits（コミット履歴）を見れば、実際に動いた時刻が全部並んでいます。 「思ったより通知が来ないな」と感じたら、ここを見てください。

パソコンは関係ありません

処理は GitHub のサーバー上で動きます。あなたのパソコンの電源が入っていなくても、 寝ていても、動き続けます。常時起動のパソコンを用意する必要はありません。

セットアップの全体像

費用について

費用は一切かかりません。 公開リポジトリ（誰でも見られる設定）なら、GitHub の自動実行は無制限に無料です。 Slack も無料枠の範囲で収まります。外部の有料サービスは一切使いません。

公開リポジトリにするということ

無料で使うには、リポジトリを公開（Public）にするのがおすすめです。 ただし公開の意味を先に知っておいてください。

公開すると、あなたの設定と監視結果は誰でも読めます。 どの物件を狙っているか（設定ファイルの中身）も、いま空いている部屋の一覧も、 リポジトリを見れば分かります。
Slack に届く通知の中身は公開されません。公開されるのは、リポジトリに置いた 設定と結果のファイルです。

知られたくない場合は非公開（Private）にもできます。その場合の違いは次のとおりです。

項目公開（Public）非公開（Private）
自動実行の費用無制限に無料月2,000分まで無料（この設定なら月およそ1,200分）
空き部屋一覧の Web 公開できるできない（GitHub Free の場合）
設定と結果が他人に見えるか見える見えない
Slack 通知どちらでも同じように届く

迷ったら公開で始めて構いません。狙っている物件が人に知られて困る、という場合だけ 非公開を選んでください。あとから切り替えることもできます。

GitHub アカウントを用意する （5分／お持ちなら飛ばす）

GitHub は、プログラムを保管して自動実行してくれるサービスです。このツールはここで動きます。

アカウントを作る

  1. https://github.com/signup を開く
  2. メールアドレス、パスワード、ユーザー名を入力して登録
  3. 届いたメールに書かれた数字を入力して、メールアドレスを確認する

プランは無料（Free）のままで構いません。有料プランは不要です。

ツールを自分のアカウントにコピーする （3分）

「フォーク」という操作で、このツールをまるごと自分のアカウントに複製します。 元のリポジトリには影響しないので、安心して操作してください。

フォークする

  1. https://github.com/tama-create/ur-monitor を開く
  2. 画面右上の Fork ボタンを押す
  3. そのまま Create fork を押す（設定は変えなくて構いません）

数秒で あなたのユーザー名/ur-monitor というリポジトリができます。 以降の作業はすべて、この「自分の方」で行ってください。

フォーク直後の注意

フォークした直後は、自動実行が止まっています。 これは GitHub の安全のための仕様です。第 9 章で有効にします。

監視する条件を設定する （10分）

config.json というファイルを編集します。ブラウザ上で直接編集できるので、 何かをインストールする必要はありません。

監視したいページの URL を調べる

  1. UR賃貸住宅のサイト を開く
  2. 住みたいエリアや駅で検索する
  3. 検索結果が一覧で出ている状態のページの URL をコピーする

たとえばこういう URL です。

https://www.ur-net.go.jp/chintai/kanto/saitama/area/208.html

config.json を編集する

  1. 自分のリポジトリで config.json をクリック
  2. 右上の鉛筆アイコン（Edit this file）をクリック
  3. 次の節の表を見ながら書き換える
  4. 右上の Commit changes... → Commit changes で保存

設定項目の意味

項目意味
search_urls 巡回するページの URL。ここに出てくる物件だけが監視対象になります。複数書けます
watch 通知する条件。building（建物名）と madori（間取り）の組。どれか1つに合えば通知
highlight_keywords Web ページ上で赤く目立たせる文字列。通知には影響しません
notify_all_new true にすると条件に関係なく全部の新着を通知。通知が多くなるので既定は false

書き方の例：

"watch": [
  { "building": "○○ハイツ", "madori": "1LDK" },
  { "building": "○○ハイツ", "madori": "2DK" }
]

これは「○○ハイツの 1LDK または 2DK」という意味です。間取り違いは行を分けて書きます。

建物名の書き方

建物名は「一部でも一致すれば OK」の判定です。短く書きすぎると、似た名前の別の建物まで通知されます。

たとえば "さくら通り" と書くと、「さくら通り第二」「さくら通り第三」にも反応します。 建物名はUR のサイトに表示されているとおり、正確に書いてください。全角スペースの有無まで一致させます。

逆に、"madori": "" のように空にすると「その条件は問わない」という意味になります。

Slack の通知先を用意する （15分）

ワークスペースを用意する

お持ちでなければ https://slack.com/get-started から無料で作れます。自分ひとりのワークスペースで構いません。

通知専用のチャンネルを作る

通知が他の会話に混ざらないよう、専用のチャンネルを作ります。

  1. Slack の左側「チャンネル」の + からチャンネルを作成する
  2. 名前を付ける（例：ur-空室通知）
  3. 公開範囲で プライベート を選ぶ ← 自分だけが見られるようにするため
  4. 作成する。メンバー招待の画面はスキップ（誰も招待しない）

Slack アプリを作る

  1. https://api.slack.com/apps を開く
  2. Create New App → From scratch
  3. アプリ名を入力（例：UR空室監視）、ワークスペースを選ぶ → Create App
  4. 左メニューの Incoming Webhooks を開く
  5. 右上のスイッチを On にする

アプリをチャンネルに招待する

Slack に戻り、7.2 で作ったチャンネルで次を入力して送信します。

/invite @UR空室監視

アプリ名は途中まで打つと候補が出るので、そこから選ぶと確実です。
プライベートチャンネルは、先に招待しておかないと次の節で選択肢に出てきません。

Webhook URL を発行する

  1. api.slack.com の Incoming Webhooks の画面に戻る
  2. 下部の Add New Webhook to Workspace を押す
  3. 投稿先で 7.2 のチャンネルを選ぶ → 許可する
  4. 表に追加された URL の Copy を押す

この URL は「鍵」です。 これを知っている人は誰でもあなたのチャンネルに書き込めます。 人に見せたり、SNS やチャットに貼ったりしないでください。

間違えて公開してしまったら、表のゴミ箱アイコンで削除し、発行し直せば無効になります。

GitHub に Webhook を登録する （3分）

Secrets とは

コピーした URL を GitHub に預けます。「Secrets」という、登録後は誰も中身を見られない保管場所を使うので、 リポジトリが公開されていても漏れません。

登録する

  1. 自分のリポジトリで Settings タブを開く
  2. 左メニューの Secrets and variables → Actions
  3. 緑の New repository secret を押す
  4. 下の表のとおり入力して Add secret
欄入力するもの
NameSLACK_WEBHOOK_URL
Secret7.5 でコピーした URL

Name は1文字でも違うと動きません。 大文字とアンダースコア（_）まで、上の表からそのままコピーして貼るのが確実です。

動かしてみる （5分）

自動実行を有効にする

  1. 自分のリポジトリの Actions タブを開く
  2. 「ワークフローを有効にしますか」という趣旨のボタンが出たら押す

手動で1回動かす

  1. 左メニューの UR賃貸監視 をクリック
  2. 右側の Run workflow ▾ → 緑の Run workflow
  3. 1分ほど待つ

結果を確認する

うまくいっていれば、次のことが起きます。

  • 実行が緑のチェックになる
  • Slack に通知が届く（初回は条件に合う部屋がすべて「新着」として通知されます）
  • リポジトリに state.json と results.html が作られる

ここまで来れば完成です。 以降は 8:00〜21:00 の間、自動で動き続けます。もう何もしなくて構いません。

通知を活かすコツ

セットアップはここまでで終わりです。この章は通知を実際に役立てるための使い方の話で、 設定作業ではありません。

スマートウォッチで受け取る

スマートウォッチをお持ちなら、Slack の通知をウォッチに転送する設定を有効にしておくことを おすすめします。

空室は早い者勝ちなので、気づくまでの数分が結果を分けます。 スマホを見ていない時間帯 — 通勤中、会議中、家事や運転の最中 — でも、 手首の振動なら気づけます。ポケットからスマホを出して確認するより明らかに速いです。

通知は強めに設定してよい

このツールは条件に合う新着が出たときだけ通知します。 毎回の実行結果を送りつけたりはしませんし、notify_all_new も既定でオフです。

つまり、通知が鳴るのは「本当に見るべきとき」だけです。 だから遠慮なく強めに設定して構いません。

Slack のチャンネル設定で 「すべての新しい投稿」 を選び、 モバイル通知もオンにしておくと取りこぼしません。専用のプライベートチャンネルを作ったのは、 この設定を他の会話に影響させずに済ませるためでもあります。

気づいたらすぐ電話する

通知には物件名・間取り・家賃と、その部屋のページへのリンクが入っています。 このリンク先が効いてきます。

  1. ウォッチが震える。条件に合う部屋が出たときだけなので、見る価値がある通知です
  2. スマホで通知のリンクをタップ。その部屋のページが直接開きます （検索し直す必要はありません）
  3. ページ中ほどの「電話で今すぐお問い合わせ」をタップして、そのまま発信

この3タップが、現状いちばん速い動き方です。 通知のリンクを物件ページ直リンクにしてあるのは、この流れを想定してのことです。

迷っている時間がそのまま不利になります。 条件を満たしているなら、まず電話で当たってから細かい検討をするほうが結果的に得です。 このツールは「気づく」までを速くしますが、その先の一手はご自身の行動しだいです。

電話でやることは「仮申込と内覧の予約」です。入居するかどうかを決めてから かける必要はありません（1.5 のとおり、UR の手続きは押さえてから内覧する 順番になっています）。とりあえず押さえて、見てから考える。これが実際の動き方です。

ショップの営業時間外（多くは10:00〜18:00、水曜休み）に通知が来たときは、 同じページの「ネットで仮申込み」から先に進めておく手もあります。

空き部屋一覧を Web で見る （任意・3分）

空き部屋の一覧を、スマホからも見られる Web ページとして公開できます。 この章はやらなくても Slack 通知は動きます。不要なら飛ばしてください。

実際にできるページ（見本）

作者が実際に運用しているページです。開いてみると、この章で作るものが分かります。

https://tama-create.github.io/ur-monitor/

見どころは次のとおりです。

  • 取得日時が上に出ます。いつ時点の情報かがひと目で分かります
  • 監視している検索URLごとに区切られて、それぞれ何件空いているかが出ます
  • NEW の付いた行が、前回の確認から新しく出てきた部屋です
  • 赤く目立つ行が、狙っている物件（設定した highlight_keywords に一致した行）です
  • 各行の「詳細を見る」から、UR の物件ページへ直接飛べます

このページは実際に動いているものなので、開くタイミングによって件数も中身も変わります。 「0 件」と表示されていても壊れているわけではありません。

外部サービスもトークンも要りません。 GitHub の設定を1つ切り替えるだけです。

反映のタイミング

監視が動いて一覧が更新されると、その内容がリポジトリにコミットされ、 自動で Web ページに反映されます。ビルドは30秒ほどで終わります。

つまりやることは最初の設定1回だけで、あとは何もしなくても最新に保たれます。

ページには noindex を入れてあるので検索エンジンには載りません。 ただしURL を知っている人は誰でも見られます。 狙っている物件を人に知られたくない場合は、この章を飛ばして Slack 通知だけを使ってください。

Slack に通知が来ない

確認すること対処
Secret の名前が SLACK_WEBHOOK_URL になっているか 1文字でも違うと読み込まれません。作り直してください
そもそも条件に合う部屋があるか ログに「新着なし」と出ていれば正常です。空きが出るまで通知は来ません
建物名が正確か UR のサイトの表記と、スペースまで一致しているか確認してください

「0 件のため前回状態を維持」と出る

これは正常な動作です。故障ではありません。

UR のサイトは、うまく読み取れずに0件になることがあります。これをそのまま信じると 「全部の部屋が埋まった」と誤解し、次に復活したときに誤った通知が飛んでしまいます。

そこで、0件だったときは前回の状態を保つようにしています。 3回連続（約1時間半）で0件が続いた場合だけ、本当に空きが無くなったと判断します。

実行が赤いバツになる

  1. Actions タブから、失敗した実行をクリック
  2. monitor をクリックしてログを開く
  3. 赤い印が付いている行を探す

よくある原因は、config.json の書き間違いです。カンマの付け忘れや、括弧の対応が合っていないと止まります。

1件も部屋が取れない

UR のサイトの作りが変わった可能性があります。その場合は config.json の selectors という項目を直す必要があり、少し専門的な作業になります。 リポジトリの Issues から相談してみてください。

使っている技術

仕組みに興味がある方向けの説明です。読まなくてもセットアップには影響しません。

技術の一覧

技術役割
GitHub Actions 決まった時刻にプログラムを自動実行する仕組み。パソコンを起動しなくても動く理由がこれです
PHP 本体のプログラムの言語。ur_monitor.php の1ファイルだけで動いています
Headless Chrome 画面のない Chrome。UR のサイトは物件情報を後から JavaScript で表示するため、 普通にページを取得するだけでは中身が空になります。本物のブラウザで開いて、 表示が終わるのを待ってから読み取っています
Slack Incoming Webhook 指定の URL にメッセージを送ると Slack に投稿される仕組み
GitHub Pages リポジトリ内の HTML をそのまま Web 公開できる仕組み。docs/ に置いたものが push のたびに自動で配信される（任意機能）
GitHub Secrets パスワードや鍵を安全に預ける場所。登録後は本人でも中身を見られません

状態の持ち方

「前回どの部屋があったか」は state.json というファイルに記録され、 実行のたびにリポジトリへ自動コミットされます。 GitHub の実行環境は毎回まっさらにリセットされ、ファイルが残らないためです。

やっていないこと

UR のサイトへの負荷を抑えるため、15分間隔を守り、URL 間に待機を入れ、 robots.txt を確認したうえで動かしています。 取得間隔を極端に短くする改造はしないでください。 相手のサーバーに迷惑がかかり、この方法自体が使えなくなります。
